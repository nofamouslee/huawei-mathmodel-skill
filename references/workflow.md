# 阶段操作与回退

每轮只执行plan中选定的阶段或任务。下列S0—S8是可分次推进的流程，不要求一次执行完毕；到指定停止点更新plan/todo并结束。实验阶段只整理研究与运行记录，不提前写论文。

## S0 接收与规划

确认训练/比赛/未知状态及请求范围。列出题面、附件、官方规则、既有文件和资源限制。读取当前输入，核对文件清单与可读性。环境检查按实际需要进行：Python/其他既定语言、必要包、求解器、图像工具；不要安装全部候选库，不检查无关的论文编译器。

若缺题面，建立简明接收记录并请求题面；不生成虚构选题或实验结果。若仅缺部分附件，标明阻塞要求，继续题意与数学分析。

完成 plan/todo 的具体化和当前预算。G0 的依据为接收报告、用户约束和规则记录。

## S1 选题与拆解

已选题直接沿用；未选题先横向读取，再比较少量候选。依据理解程度、数据支持、后续小问可解性、实现成本、验证能力和队伍优势判断。必要时做有预算的小试算，不凭第一问容易或算法熟悉程度决定整题。

拆题三遍：应用目的；数学条件与单位；逐项交付要求。记录每个要求的原文出处。画出真正的数据依赖；不要强行串成线性“问题一→二→三”。

形成 requirements.md 与 state.requirements，记录基线可行性、关键风险和备选。G1 核对所有要求，包括解释、比较、图表和附件要求。若具体要求遗漏，回到原文。

## S2 数据与假设检查

核对每份附件的结构、字段、单位、范围、主键、时间/空间/对象关联。PDF中的负号、上下标、公式和图示边界必要时视觉复核。

保留原始数据；记录派生数据规则与样本变化。异常值先解释，不能为使结果更好而随意删除。区分真实零、缺失、测量误差与极端样本。

预测问题先设计合理的按时间/对象/空间划分，再拟合预处理参数。无真实数据的机理题登记方程、边界、初值与参数来源；仿真数据明确标注。

列出关键歧义及合理解释，用简单验算、题面证据和官方答疑处理。新增条件没有改变结果是复核线索，不是必然读错：也可能是约束未活跃、资源冗余或目标饱和。

G2 检查输入含义和处理可追溯。重大歧义未决时保留条件分支或标阻塞，不静默猜测。

## S3 建模与验证设计

按每个要求交代变量及定义域、量纲、目标/演化关系、约束、假设、参数来源与估计、求解方法、输出和验收方式。

检查可辨识性、边界、数量级和可行性。附代码接口：文件格式、索引、单位、输入输出、容差、运行预算、失败状态。

选择可解释的基线和有理由的主方案；备选仅为确实存在的风险准备。事先确定主指标、对照、划分、参数选择、随机性处理、所需稳健性/敏感性分析和停止条件。

按 figures.md 建立图表计划，明确拟检验的问题、输入结果与图型。用户指定时可给出标注“拟议方法”的 GPT Image 结构提示词；不是最终论文图，不提前写论文。

G3 不要求模型复杂或一定创新，要求能回答题意、可实现且可以评价。数学或数据支持不足时返回S1/S2。

## S4 基础实现

先手算可核验实例或构造满足已知性质的小实例，再跑完整数据。逐问实现和运行，保留日志与错误。先满足硬约束，再改进目标。

核对报告与代码中的公式、单位、参数和目标方向。把优化输出独立代回原始约束；检查预测物理边界；检查仿真守恒和数值精度。

运行后登记输入、输出、日志及版本。执行失败仍登记 FAILED，不能把仅写好的代码当成实验结果。没有计算环境时交付代码、命令和所需回传项，相关检查记BLOCKED。

G4 证明最小有效路径和基础结果成立；不据此声明主方案优于基线。

## S5 改进与验证

从已观察到的误差、约束问题、运行瓶颈或不稳定性出发，每次改动附目标、对照和预算。保持数据、评价口径和约束可比。若计算预算不同，说明比较目标与限制。

区分敏感性、稳健性、不确定性和消融。按论证需要选择，不要求所有题机械执行同一套实验。验证主要结论、代表性失败、极限情形；必要时传播上游参数不确定性。

依据完整结果选择最终方案；随机性明显时报告分布或重复结果，不只挑最好一次。无收益的复杂方案如实记录。

按 figures.md 从真实结果生成实验分析图，保留代码、统一样式、源数据和逐图数值/视觉检查记录；未执行视觉检查如实记录。

G5 检查每个主要结论有适当证据；没有真实标签时使用可行性、已知性质、外部依据或理论分析，不虚称预测准确。

逐项清点本次研究范围内的实验计划。基础实验、比较实验和必要验证均应有实际结果、日志、检查结论及局限；尚有必要实验未执行、失败待处理或证据过期时，论文写作保持关闭。S5完成后若已到本轮停止点，只交付结果报告，不自动开始S6。

## S6 Markdown 论文

先读取写作指南并核验写作前提。全部计划内实验和必要验证完成、结果有效且本轮包含写作时，才开始paper/paper.md。按题目动态决定章节数量与论证结构，写清每问的建模依据、数学表达、求解、结果、检验及实际含义。

按 figures.md 统一实验图风格并复核源数据。框架图/流程图默认交付基于实际方法的 GPT Image 提示词包，不自动生成图片。提示词完成与成图验收分开登记；必要图片未生成不能视为完成。已有合格图片用相对路径，不能引用不存在的图片或临时绝对路径。

关键数字使用证据绑定注释；摘要最后根据已确认结果定稿。补齐引用和应有的AI使用说明。

G6 核对题目覆盖和表达一致性，不以字数、图数量或排版华丽程度判断完成。

## S7 最终验收

分别审查题意覆盖、数学依据、实现结果、文稿表达。让检查具有相对独立性：原约束复算、小实例手算、独立实现、重新读题或队内交叉复核；无需默认多代理。

阅读实际结果、日志、关键代码和来源，记录检查内容及结果。合理安排复现范围；无法复现的部分如实列为未执行，必要检查不能被降成警告。

运行结构/证据审计脚本。脚本检查文件哈希、依赖、状态、绑定数值和图片；人工/模型评阅检查论证、来源语义、模型适用性与未绑定数字。

G7 记录真实检查。发现数据/模型/实现错误分别返回S2/S3/S4；仅表达或路径错误返回S6。

## S8 交付归档

确认Markdown、引用图像和所需复现材料齐全；在delivery.md记录交付范围、主要结论、完成验证、局限、使用方式和官方提交状态。

更新plan/todo并记录G8后进行完整审计与冻结。冻结意味着保留版本快照；修改需要新版本或明确解除旧冻结并保留历史，重新检查受影响内容。

不要为Markdown任务生成论文模板、编译PDF或执行官方提交。若用户之后追加官方提交需求，重新核对当届格式与时间，并按新授权完成。
